# 11: Excel Integration

**What to build:** an Admin adds an Integration of kind Excel: connects a Microsoft 365 account, and Vink makes a new workbook with a table in that OneDrive (or a SharePoint site the account can reach). Approvals add rows exactly as for Google Sheets (same row building, ADR 0009), and access lost / Reconnect works the same way. The docs say that many companies need their IT admin to consent to the Vink app first, and how they do that.

**Blocked by:** 08, 09

**Status:** done (on integrations, open checks listed)

## Comments

**2026-10-06 (implementer):** Built on `int/11-excel`.

- Choices. Sign-in is on `https://login.microsoftonline.com/organizations/` (multi-tenant, work or school accounts). Personal Microsoft accounts are not supported: Graph's Excel API can't add table rows for them ("Create TableRow": personal account "Not supported"), and the ticket is about Microsoft 365 business tenants. Scopes are `offline_access https://graph.microsoft.com/Files.ReadWrite`. `Files.ReadWrite` is the least the Excel API takes (`Files.ReadWrite.AppFolder` isn't listed for the workbook calls), it covers only the account's own OneDrive, and it needs no admin consent by itself. `User.Read` isn't asked for, because Vink never reads the profile. Vink uses OneDrive, not SharePoint: a site would need `Sites.ReadWrite.All`, which always needs an admin. The sign-in uses `prompt=select_account`, never `prompt=consent`: in a tenant where only the IT admin may consent, a forced consent page blocks every user, even after the admin consented.
- Kind: `integrations` has a third member, `kind: "excel"`, with `refreshToken` (encrypted), `driveId`, `itemId`, `tableId` (so a moved or renamed file still works), `workbookUrl` and `needsReconnect`. `integrations.list` returns the workbook link as `url`. `update` and `signingSecret` refuse it, like Sheets.
- Microsoft client: `convex/lib/microsoft.ts`, interface `MicrosoftClient`, object `microsoft`, plain `fetch`, no SDK. `createWorkbook` uploads an .xlsx that Vink builds in code (`emptyWorkbook`: a stored ZIP of five XML parts, worksheet "Vink" with the header in row 1, frozen) to `PUT /me/drive/root:/<name>.xlsx:/content?@microsoft.graph.conflictBehavior=rename`, then `POST …/workbook/tables/add` over the header. `read` takes `headerRowRange` and the `delivery_id` column's `dataBodyRange`. `append` adds each new column with `columns/add` (`index: null`, `name`), then the rows in one `rows/add`. Text is written with a leading apostrophe (Excel's text mark), so no value becomes a formula, a number or a date. A new Excel table always comes with one empty row: after the first rows are added (`rows/add` answers `index: 1`), Vink deletes row 0 if it is empty, best-effort. `fakeMicrosoft` in `convex/test.setup.ts` keeps workbooks in memory.
- Refresh tokens rotate: `MicrosoftClient.accessToken` returns the new refresh token too. **Seam change:** `SendDetails` has `keepRefreshToken(token)`. `deliveries.attempt` and `integrations.testSend` pass `refreshTokenKeeper(ctx, integration)` (`lib/accounts.ts`), which calls the internal mutation `integrations.keepRefreshToken`. That stores it encrypted only while the stored token is still the one the send started from, so a Reconnect in between wins. The Excel adapter stores it before it writes. `excel.connect` stores the newest token too.
- Connect: `excel.connectUrl` (Admin), Next route `app/api/integrations/microsoft/callback`, `excel.connect`, results as `?excel=` connected · reconnected · no_access · no_sheet_access · admin_consent · denied · failed. The state is the signed `lib/oauthState.ts` state of 08. Reconnect: `microsoftAccount` in the `providers` map of `lib/accounts.ts`; `integrations.reconnectUrl`/`reconnect` work unchanged. `canReach` opens the table; with `Files.ReadWrite` another account gets 403/404, so the answer is `no_sheet_access`. Revoke on remove is a no-op: Microsoft has no endpoint that takes back one app's refresh token (`revokeSignInSessions` would sign the person out everywhere). The token is deleted with the Integration.
- Outcomes: no answer, 408, 423 (workbook locked), 429 and 5xx are retried with Retry-After. 404 fails ("The workbook is gone: it, or its Vink table, was deleted"). Other 4xx fail ("Microsoft refused the write (<status>)"). 401 and the token errors `invalid_grant`, `interaction_required` and a consent error fail at once with `cause: "access_expired"`, so 09's "Needs reconnecting" and notice apply. A Delivery whose `delivery_id` is already in the table adds nothing ("Already in the workbook").
- Admin consent: `needsAdminConsent(error, description)` recognises `consent_required`, AADSTS65001, 90094 and 90095 (and "admin consent/approval" in the text). The callback checks Microsoft's `error`/`error_description` on the redirect, and `excel.connect` checks the token endpoint. Then the Integrations page shows an alert (NL + EN) that says the IT admin must approve Vink first, with `https://login.microsoftonline.com/organizations/adminconsent?client_id=…` and a copy button (`excel.adminConsentUrl`, Admin; null when the env var is not set). A plain `denied` toast says to check that note too, because Microsoft's "Need admin approval" page can come back as a normal cancel (AADSTS65004). Docs: the Excel part of the New Integration dialog always has "Does your company need IT admin approval?". It says that many companies need this, who can do it (Cloud Application Administrator or Application Administrator), the Entra path (Enterprise apps, Vink, Permissions, Grant admin consent), and the link. It is in the app, not on the Developers page, to stay out of ticket 12's sections.
- UI: Excel is a third kind in the dialog (FileSpreadsheet icon), with "Connect Microsoft account", short notes, the admin-consent box, "Open the workbook" and "Reconnect Microsoft account". The card shows an "Excel" badge. The test-send text says rows go to the workbook. Copy is in NL and EN, and the Dutch server errors are in `lib/server-errors.ts`. The demo is unchanged: it doesn't show the Integrations page. `lib/platforms.ts` and `llms.txt` are unchanged, as decision 11 says: add Excel after the real checks.
- Proof: `convex/excel.test.ts` (20, on `fakeMicrosoft`): consent URL; connect makes the workbook with header table and stores the newest token encrypted; state of another Admin, Org or expired refused; Member refused (connect and admin link); admin consent result + link; no files scope; Approval rows; every send stores the rotated token (fails when the adapter doesn't keep it); new Field column; 429/504 retried; 403 refused; 404; access expired fails at once, notice, needs reconnecting; lost answer not written twice; test-send rows; rename/no Webhook functions; Reconnect then re-send skips rows already there; another account refused; Reconnect with admin consent; remove. `convex/lib/microsoft.test.ts` (9, the real client against a stubbed `fetch`): token rotation request, refused grants vs Vink's own bad secret, admin-consent detection, upload + `tables/add` requests, read URLs, columns/rows add bodies (apostrophe text), empty-row removal, Retry-After/403/404/401, and the .xlsx parts. The generated .xlsx also passes `unzip -t`, Python `zipfile.testzip()` and loads in openpyxl (sheet "Vink", header row, frozen at A2). Full suite: 516/516. `tsc` and `eslint` are clean.

Open checks (need real accounts or a person with access):
1. Microsoft Entra app registration: multi-tenant ("Accounts in any organizational directory"), Web redirect URI `https://vink.page/api/integrations/microsoft/callback` (plus dev if wanted), a client secret, and the delegated Graph permissions `Files.ReadWrite` and `offline_access` under API permissions (admin consent through `/adminconsent` grants what is listed there). Publisher verification (a Microsoft AI Cloud Partner Program ID), because many tenants allow user consent only for verified publishers.
2. Set `MICROSOFT_OAUTH_CLIENT_ID` and `MICROSOFT_OAUTH_CLIENT_SECRET` on the Convex deployments (dev and prod). `SITE_URL` must be the public origin. Note when the client secret expires (24 months at most).
3. With a Microsoft 365 business tenant on prod: connect, then open the workbook and check the "Vink" sheet, the table and the header. Do a test-send and a real Approval of a Form with a List. Check the rows, that the empty first row is gone, that text like `00123` or `=1+1` stays text, and that a new Field adds a column on the right. These Graph details are unconfirmed: `columns/add` with `index: null` and `name`, and `DELETE rows/itemAt(index=0)`.
4. Admin-consent path: in a tenant with user consent off, connect, and check that Microsoft's "Need admin approval" page leads to the alert (`admin_consent`) or the denied toast. Open the admin-consent link as a Cloud Application Administrator, approve, and connect again. Check where Microsoft sends the admin afterwards (the callback sends a request without state to `/app`).
5. Access lost: revoke Vink at myapps.microsoft.com (or an admin removes the grant), approve a Document, and see "Access expired" and "Needs reconnecting". Reconnect with the same account and re-send. Also reconnect with another account and see the refusal.
6. After 90 days with Deliveries, check that the Integration still works (rotated refresh tokens are kept).
