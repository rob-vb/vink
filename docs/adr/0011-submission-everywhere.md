# One word, Submission, from the app to the database

The app showed a Submission (nl: Inzending), but the code, the Convex tables, the public API, the Webhook event and the Make, Zapier and Power Automate apps said Document. So a developer, an agent and an API user each had to translate. Since the input became emails and photos too (ADR 0010), "document" was also wrong for users: an email is not a document to them. We renamed the concept to **Submission** everywhere: the identifiers and files, the tables (`submissions`, `submissionEvents`, `submissionCounts`, `submissionId` fields), the app route `/app/o/[slug]/submissions/…`, the API paths `/v1/submissions` and `/v1/forms/{form_id}/submissions`, the schema `Submission`, the event `submission.approved`, the envelope key and the spreadsheet column `submission`, the delivery id `sub_<id>`, and the integrations' modules and triggers.

Vink had no customers, and the Make and Zapier apps were not live, so we kept no aliases, no old paths and no migration: the existing Documents on dev and prod (test data) were deleted, with their files and child rows, before the new schema was pushed. We rejected Stuk, Record, Bericht and keeping Document: Submission is what the user already reads, and what the sender does.

"document" stays where it means a paper or a file in plain English: marketing and legal copy, the default file name `document.pdf`, the "OpenAPI document", the Jev prompts in `convex/lib/matcher.ts`, `verifier.ts` and `routerPlan.ts` (their state key `document`, tuned on the eval), and the eval fixtures in `fixtures/documents/`.
